# 仪器与精密测量领域英文文献专业翻译范式

> 版本：V1.8（机器可验证QA、证据优先、状态机与Release Gate强化版）
> 适用范围：仪器科学、精密测量、计量学、光学工程、激光干涉、光栅干涉、光电检测、位移测量、信号处理、机械误差与多自由度测量等英文科技文献。  
> 目标：技术含义准确、术语统一、公式可靠、图片与表格完全忠实、跨章节逻辑一致，并便于基础较弱的研究生长期阅读和引用。  
> 核心原则：**翻译质量高于速度、篇幅和处理时间。不要人为设置思考时长或校验轮次上限；单篇文献的分析、翻译、核验和修改可以超过30分钟，并应持续循环，直至达到本范式规定的质量门槛。**

 > 本次修订重点：在V1.7全部技术质量规则不降低的前提下，引入**证据优先执行协议、阶段状态机、机器可验证检查和统一Release Gate**。凡能够通过文件系统、PDF解析、PDF渲染或程序检查客观验证的项目，必须实际执行验证并保存结果；不得以“预计正确”“生成成功”“链接看起来正常”或语言推断代替检查。尤其是最终PDF存在性、可打开性、页数、逐页渲染、实际basename、URL编码污染、元数据和最终文件一致性，必须在正式V1发布前形成可定位的PASS/FAIL记录。若工具能力不足以完成某项强制验证，该项必须标记为“未验证/阻断”，不得声称终审通过。

## 0. 执行协议：证据优先、状态机与机器验证

本节是V1.8的执行层总则。后续各章节规定“检查什么”，本节规定“怎样证明真的检查过”。若本节与后续重复条款发生表述差异，以**更严格、可验证、可追溯**的要求为准。

### 0.1 证据优先于声明

任何“已完成、已通过、无问题、终审通过、可交付”等状态，都必须由真实存在且可定位的检查记录支持。

强制原则：

1. **能机器验证的，不得只靠语言判断。**
2. **能从最终文件验证的，不得只验证排版源或中间文件。**
3. **能读取实际值的，不得用预期值代替。**
4. **检查记录必须先于完成声明产生。**
5. **工具无法完成强制检查时，必须标记“未验证/阻断”，不得推定通过。**
6. 用户未要求查看全部内部记录时，可以不展示证据包，但证据必须真实存在。

### 0.2 阶段状态机

全文翻译采用单向状态机管理：

```text
INPUT
  ↓
INVENTORY（结构盘点）
  ↓
TERM-FROZEN（术语冻结）
  ↓
DRAFT-A
  ↓
DRAFT-B
  ↓
QA-1
  ↓
REVISE
  ↓
QA-2（独立、盲审式）
  ↓
RC
  ↓
RELEASE-GATE
  ↓
V1-RELEASED
```

规则：

- 任一阶段发现P0或技术性P1，必须退回相应修订阶段；
- QA-2发现新的P0或技术性P1时，QA-1评分和“可交付”结论失效；
- `V1-RELEASED` 只能由 `RELEASE-GATE = ALL PASS` 触发；
- 不允许从Draft、QA或RC直接跳到正式V1；
- 文件名中出现V1不能证明状态已经到达 `V1-RELEASED`。

### 0.3 必须机器验证的项目

下列项目凡工具条件允许，必须通过实际工具或文件系统执行，不得仅靠目视推断或计划性表述：

| 项目 | 最低验证动作 | 通过条件 |
|---|---|---|
| 最终PDF存在性 | 实际读取文件系统路径 | 文件真实存在 |
| PDF可打开性 | 用PDF解析器/阅读器实际打开 | 无损坏、可读取 |
| 页数 | 从最终PDF读取页数 | 与发布记录一致，且结构覆盖无缺页 |
| 最终渲染 | 将最终PDF逐页渲染 | 无渲染失败；逐页检查完成 |
| 公式页 | 放大查看含公式页面 | 符号、上下标、编号无缺失或变形 |
| 图/表页 | 放大查看含图、原始表格图像页面 | 无裁切、模糊、错序或缺失 |
| PDF元数据 | 从最终PDF实际读取 | 与原文及排版要求一致 |
| 实际basename | 从最终文件路径读取basename | 与预期basename完全一致 |
| URL编码污染 | 对实际basename检查 `%[0-9A-Fa-f]{2}` | 无误编码匹配 |
| 文件一致性 | 记录最终文件大小；必要时计算校验和 | 发布对象就是通过RC检查的同一文件 |

其中“实际basename”是文件系统中的真实文件名；网页或下载链接中的 `%20` 可能只是传输层编码，**不能据此推断实际basename**。必须读取最终文件路径后再判断。

### 0.4 Release Gate记录格式

正式发布前必须形成一份简短、可复核的机器发布记录，至少包括：

```text
Expected basename: <预期正式文件名>
Actual basename:   <从文件系统实际读取的basename>
Expected == Actual: PASS / FAIL
URL-encoding regex %[0-9A-Fa-f]{2}: PASS / FAIL
Final PDF exists: PASS / FAIL
Final PDF opens: PASS / FAIL
Page count: <实际页数>
Page-by-page render: PASS / FAIL
Metadata check: PASS / FAIL
RC identity/file consistency: PASS / FAIL
Release Gate: ALL PASS / BLOCKED
```

`Release Gate: ALL PASS` 之前：

- 不得生成或发送正式V1下载链接；
- 不得声称“终审通过”“正式完成”；
- 不得用高分抵消未验证项；
- 不得把“文件生成成功”当作“质量检查通过”。

## 1. 总体目标

翻译结果应达到以下标准：

1. 不仅“中文通顺”，还必须保持原文的技术含义、限制条件、逻辑关系和物理量定义。
2. 图片必须直接取自英文原始PDF，不重绘、不重组、不翻译图内文字。
3. 公式必须以英文原始PDF页面图像为最终依据逐字符核对，并保留公式编号；不得仅依赖PDF解析文本、OCR结果或上一版译文。
4. 表格必须作为英文原始PDF的高分辨率裁剪图原样保留；表号、表题、列名、行名、数据、单位、注释和表内公式均不翻译、不重排、不重新录入、不重建为可编辑表格。
5. 必须进行跨章节核验，主动发现原论文内部的单位错误、图号错误、章节号错误、术语矛盾、公式简化及图内参数冲突。
6. 每幅图中的尺寸、周期、频率、波长、角度、效率、材料、坐标轴、图例、符号和结构参数，必须与图题、正文、表格和结论逐项交叉核验。
7. 作者姓名、机构、期刊、卷期、页码、DOI、基金、ORCID等属于论文元数据，原则上保持原文，不根据拼音猜测中文姓名。
8. 参考文献直接照搬英文原文，不翻译题名，不重新著录，不使用OCR重排。
9. 最终文件应便于研究生阅读，同时保留足够的专业严谨性。
10. 正文、页眉、页脚、封面和文件属性中不得出现“由ChatGPT翻译”“AI翻译”“机器翻译”等说明；正式文件名按本范式使用“_GPT译_V1”等版本标识。
11. 翻译、排版和审校过程中产生的内部文件不得使用正式V1、V2、V3版本号，应使用Draft-A、Draft-B、QA-1、QA-2、RC等内部标识。
12. 第一次向用户提供下载链接的文件，必须已经满足全部终审条件，并直接命名为正式V1；不得把“首次完整翻译候选稿”当作V1提前交付。
13. 完成候选稿后必须先进行内部评分。满分10分，综合评分低于9.2分时，不得向用户提供文件或下载链接。
14. 评分不足9.2分时，必须继续执行“对照原文—发现问题—修改译文—跨章节核验—重新排版—重新评分”的闭环，不得以“已经基本可用”为理由提前停止。
15. 最终交付不仅要求总分达到9.2分，还必须满足各关键分项最低分、无P0问题、无未解决的技术性P1问题，并通过最终PDF逐页渲染检查。
16. 独立公式必须通过“原文页图—排版源中的结构化数学表达—最终PDF渲染”三层独立核验；表格及表内公式则通过“原文页图/原始裁剪图—排版源嵌入资产—最终PDF渲染”三层图像保真核验，任一层未通过不得交付。
17. 对原文公式、关键数值或算法系数的疑似错误，默认保留原文并增加译校注，不得静默改写为译者认为正确的形式。
18. 第二轮终审必须从英文原始PDF重新开始，以寻找第一轮遗漏的新问题为主要目标；若发现新问题，上一轮评分和“可交付”结论立即失效。
19. 正式交付前必须形成可追溯的内部证据包，至少包括结构盘点表、术语表、公式审计表、图文参数一致性表、原始表格图像保真与技术信息核验表、问题清单、两轮评分记录和PDF逐页检查记录。
20. 任何“已完成”“已通过”“无问题”“终审通过”等声明，必须与可定位、可检查的记录一一对应；缺少证据时只能写“尚未完成”“未验证”或“仅完成初步检查”。
21. 评分必须按“逐项检查—登记问题—问题分级—逐项扣分—分项汇总—总分计算—硬门槛判断”的顺序产生，禁止先确定总分再反向补写理由。
22. 在完整分项表、扣分表和硬门槛记录形成前，不得给出精确总分；只有定性检查时应给出区间或标记“暂不评分”。
23. 对外报告的正式评分最多保留一位小数；不得用无计算依据的两位小数制造经过精密量化的假象。
24. 公式三层核验、QA-2独立终审、技术性P1清零、最终PDF逐页检查或交付证据包中任一关键项缺失时，不得认定为正式终审通过。
25. 第二轮独立终审在形成自己的问题清单前，不得读取或继承第一轮总分和“可交付”结论；不得以确认第一轮结论为目标。
26. 实验结果章节必须执行“结论—数据反证式核验”，检查提高、降低、保持、无影响、显著等表述是否真正得到图表和数值支持。
27. 正式V1文件名受发布锁控制：只有RC全部门槛通过后方可生成；若交付后发现本应在终审前发现的P0或技术性P1问题，必须撤销其“终审通过”状态并记录流程失效原因。
28. 正式交付PDF的实际文件系统名称必须与命名规范一致并保持正常可读字符；不得把URL百分号编码写入实际文件名。下载链接需要编码时由传输层处理，发布前必须读取实际basename并检查。

## 2. 输入文件与权威顺序

### 2.1 必需输入

至少上传：

- 英文原始PDF；
- 如有旧译文，可作为问题参考，但不得作为事实依据。

可选上传：

- 术语表；
- 实验室已有中文规范；
- 作者公开的中文论文；
- 用户指定的排版样式；
- 以前版本及校验意见。

### 2.2 权威顺序

发生冲突时，按以下顺序处理：

1. 英文原始PDF正文、公式、图表；
2. 同一论文其他章节的交叉证据；
3. 图题、图内标注和公式定义；
4. 论文官方网页或出版社元数据；
5. 作者其他公开论文中的稳定术语；
6. 已有中文译文；
7. 自动翻译结果。

已有译文不得覆盖英文原文。

## 3. 文件命名与内部阶段标识

必须严格区分：

- **内部候选稿标识**：仅用于翻译、排版、校验和修订过程，不得发送给用户；
- **对外正式版本号**：仅用于已经通过全部质量门槛并实际向用户交付的文件。

### 3.1 内部候选稿标识

内部过程文件不得使用V1、V2、V3等正式版本号。建议使用：

```text
<英文原文标题>_Draft-A.md
<英文原文标题>_Draft-B.md
<英文原文标题>_QA-1.pdf
<英文原文标题>_QA-2.pdf
<英文原文标题>_RC.pdf
```

推荐含义：

```text
Draft-A：首次完整翻译候选稿
Draft-B：正文、术语、图表和公式修订候选稿
QA-1：第一轮独立审校候选稿
QA-2：第二轮盲审式独立终审候选稿
RC：满足硬门槛后的正式交付候选PDF
```

这些文件均属于内部过程文件：

- 不得向用户提供下载链接；
- 不得声称“已完成”“终审通过”或“最终交付”；
- 不得占用正式V1、V2等版本号；
- 内部修改多少轮都不影响对外版本号。

### 3.2 对外正式版本格式

只有满足本范式全部停止条件后，第一次向用户交付的文件才命名为：

```text
<英文原文标题>_GPT译_V1.pdf
```

例如：

```text
Displacement measuring grating interferometer a review_GPT译_V1.pdf
```

### 3.3 正式V2及后续版本的适用条件

正式V2、V3等只用于V1已经向用户交付后出现下列情况：

- 用户提出新的明确修改要求；
- 用户提供新的术语规范、排版规范或实验室标准；
- 获得新的原始资料、补充材料或作者说明；
- 出版社页面、勘误或论文版本发生更新；
- 在正式交付后发现新的、此前未能获得证据支持的问题；
- 用户要求改变用途，例如制作中英对照版、投稿校样版或教学版。

仅仅因为内部候选稿需要继续校验和修订，不得生成正式V2。

### 3.4 其他文献示例

例如英文题目为：

```text
A compact heterodyne grating interferometer for displacement measurement
```

第一次正式交付文件为：

```text
A compact heterodyne grating interferometer for displacement measurement_GPT译_V1.pdf
```

### 3.5 文件名清理

当原题包含Windows文件名禁用字符时：

```text
\ / : * ? " < > |
```

只替换这些禁用字符，其他标题文字、大小写和词序保持不变。建议用短横线或全角符号替换，不要擅自改写题目。

### 3.6 实际文件名与URL编码隔离

生成正式PDF时，必须严格区分：

- **实际文件系统中的文件名（basename）**；
- **网页或下载链接中的URL编码形式**。

实际保存到文件系统中的文件名必须使用正常可读字符，不得将URL百分号编码写入实际文件名。

例如，正确的实际文件名：

```text
High-Precision Measurement of Microscales Based on Optoelectronics and Image Integration Method_GPT译_V1.pdf
```

错误的实际文件名：

```text
High-Precision%20Measurement%20of%20Microscales%20Based%20on%20Optoelectronics%20and%20Image%20Integration%20Method_GPT译_V1.pdf
```

强制规则：

1. 空格在实际文件名中保持为空格，不得主动替换为 `%20`。
2. 中文字符及其他合法字符不得主动转换为百分号编码。
3. `%20`、`%2F`、`%3A` 等URL编码只允许存在于链接传输层，不得写入实际文件系统文件名。
4. 生成正式文件时必须先以未编码的正常文件名保存，再由系统或链接层按需要处理URL编码；不得预先对实际文件名执行URL encode。
5. 创建正式文件后，必须从最终文件路径**实际读取** basename，不能使用计划中的文件名、代码变量、Markdown链接文字或浏览器显示名代替。
6. 必须比较 `Expected basename` 与 `Actual basename`；二者必须逐字符一致。
7. 必须对 `Actual basename` 执行 `%[0-9A-Fa-f]{2}` 检查。若匹配到由URL编码误写形成的序列，当前发布立即判定为FAIL，先重命名或重新生成，再重新读取basename复验。
8. 对于网页或下载链接中自动出现的 `%20`，只能视为传输层表现；不得把链接字符串反向写回实际文件名，也不得仅依据链接判断实际basename是否正确。
9. 正式交付物只生成PDF；不得为了交付流程额外生成同名DOCX。
10. 发布记录必须保存 `Expected basename`、`Actual basename`、正则检查结果和最终文件路径；缺少这些记录时，不得声明“实际文件名检查通过”。

## 4. 最终交付物

本节所称“交付物”仅指已经通过全部终审门槛的正式文件。内部Draft、QA和RC文件不属于交付物，不得向用户提供。

默认且正式只输出一份：

1. **专业中文阅读版PDF**。

不再默认生成或交付DOCX。用户明确要求其他辅助材料时，可以另外输出术语表、译校问题清单、Markdown版翻译范式、单独图片文件夹或公式清单；这些辅助材料不改变“论文正式交付物仅为PDF”的规则。

### 4.1 PDF要求

- A4版式；
- 不设置空白封面；
- 第一页直接进入论文题目、作者、机构和摘要；
- 无模型或平台说明；
- 图表完整；
- 公式清楚；
- 无乱码、越界、重叠、孤立标题和无意义空白页；
- PDF文本应尽可能可搜索、可复制；
- 最终PDF必须逐页渲染检查，并在含公式、图、原始表格图像和特殊符号的页面进行放大检查。

### 4.2 排版源与内部工作文件要求

PDF可以由Markdown、LaTeX、HTML、排版软件项目文件或其他结构化排版源生成。内部排版源仅用于制作和核验，不作为默认交付物。要求：

- 正文应保持可编辑的结构化文本，避免整页栅格化；
- 独立公式应使用结构化数学表达（如LaTeX、MathML或等效公式对象），不得用OCR得到的位图公式替代；
- 图片必须为英文原始PDF的原图/高分辨率裁剪资产；
- 论文表格同样使用英文原始PDF裁剪图，保持英文原样，不翻译、不重建；
- 参考文献可直接使用原论文页面图像；
- 不因排版源的便利性而破坏公式、图像、表格或参考文献保真性。

## 5. 总体工作流程

不得直接把全文交给自动翻译后排版，也不得在候选文件刚生成后立即交付。采用“九阶段制作 + 两轮独立终审 + RC + 机器Release Gate + 正式发布”的流程。

内部流程为：

```text
INPUT
→ 结构盘点
→ 术语冻结
→ 正文翻译
→ 原图处理
→ 公式处理
→ 原始表格裁剪与保真核验
→ 元数据与参考文献处理
→ 跨章节核验
→ 八轮质量检查
→ Draft-B修订
→ QA-1独立审校
→ 修订
→ QA-2盲审式终审
→ RC
→ Release Gate（机器验证 + 发布记录）
→ 正式V1交付
```

其中Draft-A、Draft-B、QA-1、QA-2和RC均为内部文件，不得对外发送。**只有Release Gate全部PASS后，才允许生成正式V1文件名和下载链接。**

## 6. 第一阶段：文献结构盘点

翻译前先阅读全文，建立结构清单：

- 原文页数；
- 一级、二级、三级章节；
- 图数量及所在页；
- 每幅图及每个子图中的尺寸、周期、频率、波长、角度、材料、效率、坐标轴、图例和结构参数；
- 表数量及所在页；
- 公式数量及编号；
- 含公式的表格、算法表、矩阵、系数向量及其所在页；
- 公式首次定义页、后续引用页和疑似量纲/符号冲突位置；
- 参考文献起止页及正文/致谢与参考文献的页面分界位置；
- 作者、机构、DOI、基金、ORCID；
- 缩写首次出现位置；
- 可能存在的原文错误。

输出内部检查表，例如：

| 项目 | 数量/位置 | 核验状态 |

| 正文页数 | 24页 | 已确认 |
| 图 | 图1—图18 | 已确认 |
| 图内参数清单 | 图1(a)—图18(d) | 已建立 |
| 表 | 表1—表2 | 已确认 |
| 公式 | 式（1）—式（17） | 已确认 |
| 算法表/系数向量 | 表2，共4组算法 | 已确认 |
| 参考文献 | 第18—24页 | 已确认 |

完成盘点后再开始翻译。

### 7.2 术语冻结

正式全文翻译前冻结术语表。后续发现更准确译法时：

1. 记录修改理由；
2. 全文搜索；
3. 统一替换；
4. 再检查图题、表格和译校注；
5. 禁止只修改局部。

### 7.3 语境型术语判别

有些英文词不能按字面或固定词典机械翻译，必须结合器件类别、物理量定义和所在句子的技术功能判别。例如：

- `raster scanning` 在成像与表面测量中通常译为“栅格扫描”或“逐行栅格扫描”，不得因同段出现 diffraction grating 而误译为“光栅式扫描”；
- 相机参数语境中的 `well depth`、`full-well capacity` 或作者不够规范的 `quantum well depth`，应结合定义译为“满阱容量”或“像素电荷阱容量”，不得机械译为半导体物理中的“量子阱深度”；
- 物镜语境中数值接近1的 `effective aperture`，应核对其是否实指“有效数值孔径”，不能不加判断地译为几何口径；
- 多波长干涉中的专有方法名称，如 `method of excess fractions`，必须查阅可靠中文专业文献或实验室规范后冻结译法，不得只凭字面猜译。

语境型术语冻结前必须回答：

1. 该词在本句中属于器件、物理量、算法、扫描方式还是普通描述？
2. 其数值、单位和定义是否支持当前译法？
3. 同一领域的中文标准、教材或高质量论文通常如何使用？
4. 当前译法是否会与同段出现的另一专业概念混淆？

若无法确定，应保留英文术语并标记待核对，不得强行中文化。

## 8. 第三阶段：正文翻译

### 8.1 翻译原则

正文翻译应做到：

- 保留原文事实；
- 保留原文不确定性；
- 保留条件、范围和限制；
- 保留因果、转折和比较；
- 不把推测译成结论；
- 不把“可”“可能”“有助于”译成“必然”“完全”“消除”；
- 不加入原文没有的技术结论；
- 不用科普改写替代论文正文；
- 不机械逐词直译。

### 8.2 允许的处理

允许：

- 拆分过长英文句子；
- 调整中文语序；
- 补出中文主语；
- 将代词还原为明确对象；
- 将省略的逻辑连接词显式化；
- 对原文明显病句进行不改变技术含义的顺译。

### 8.3 禁止的处理

禁止：

- 为了“读起来高级”而扩写；
- 将工程推论直接写成原文事实；
- 将accuracy、precision、resolution混为“精度”；
- 将two-DOF统一写为“二维”；
- 把器件功能写成绝对效果；
- 把原文范围扩大或缩小；
- 删除看似重复但承担承上启下作用的句子。
- 当原文给出的术语名称与其数学定义互相矛盾时，不能只照译名称而忽略定义，例如把“噪声/信号之比”直接称作“信噪比”；应保留原文并增加译校注。
- 当原文数值与基本公式明显不一致时，不能静默照抄后结束核验；应进行复算并透明说明疑点。

## 9. 第四阶段：图片处理

图片处理是本范式的强制项。

### 9.1 唯一允许来源

图片必须来自：

- 英文原始PDF内嵌图像；
- 或英文原始PDF页面的高分辨率裁剪。

不得从旧译文、网页截图或自动识别结果中取图。

### 9.2 绝对禁止

不得：

- AI重绘；
- OCR后重新排版；
- 翻译图内英文；
- 替换图中器件符号；
- 移动箭头；
- 修改波形；
- 调换子图；
- 删除空白；
- 重新拼接局部图；
- 生成“更清晰”的相似图代替原图；
- 修改坐标轴、单位、图例和曲线颜色。

### 9.3 裁剪规则

- 以整幅图为单位；
- 四周保留3～5 mm安全边距；
- 包含全部子图编号；
- 包含完整坐标轴、图例和注释；
- 不裁掉图中看似多余的留白；
- 不把原英文图题裁入图片，中文图题另排；
- 输出分辨率建议300～400 dpi；
- 不等比例拉伸。

### 9.4 逐图验收

逐图验收不能只确认“图片没有被改动”，还必须实际读取图内技术信息。每张图及每个子图必须核对：

- 图号；
- 子图数量；
- 子图顺序；
- 子图编号；
- 光路线条；
- 箭头方向；
- 器件缩写；
- 波形顺序；
- 坐标轴；
- 单位；
- 图例；
- 版权来源；
- 清晰度；
- 图内尺寸、周期、频率、波长、角度、效率、材料和结构参数；
- 图内参数与图题、正文、表格、公式和结论是否一致。

例如四相探测图必须保持：

```text
0°、90°、180°、270°
```

不得变为其他顺序。

### 9.5 图内参数—图题—正文—表格—结论五向核验

对含有技术参数的每幅图，必须建立核验表，不能只凭视觉浏览判断“无问题”。

| 图号 | 子图 | 图内参数/文字 | 图题 | 正文 | 表格/结论 | 是否一致 | 处理方式 |
|---|---|---|---|---|---|---|---|
| 图1 | (h) | \(P_x=6.10\,\mathrm{mm}\) | 5.22 mm | 5.22 mm | — | 否 | 保留原文并增加译校注 |

强制读取和记录的内容至少包括：

- 几何尺寸和周期；
- 工作频率、波长和带宽；
- 入射角、衍射角、转角和方向；
- 效率、损耗、分辨力、误差和不确定度；
- 材料、器件型号和实验条件；
- 坐标轴、单位、图例、颜色和线型；
- 图内变量与正文公式变量的对应关系；
- 图内数值与表格及结论中的重复数据。

若图内标注、图题、正文、表格和结论之间不一致：

1. 不得自动选择其中一个并静默统一；
2. 应保留作者原文事实层；
3. 给出最小必要的译校注；
4. 有充分证据时说明更可能正确的来源；
5. 没有充分证据时明确标记“需作者或原始数据确认”。

## 10. 第五阶段：公式处理

### 10.1 公式录入

公式录入的最终依据必须是英文原始PDF的页面图像或高分辨率截图。PDF解析文本、OCR、旧译文和代码提取结果只能用于辅助定位，不得作为唯一依据。

公式必须与原文逐项核对：

- 字母大小写；
- 希腊字母；
- 上下标；
- 正负号；
- 分数；
- 括号；
- 指数；
- 三角函数；
- 公式编号；
- 正文中的变量解释；
- 拉丁字母与希腊字母是否混淆，如 v/ν、u/μ、n/η、w/ω；
- 数字与字母是否混淆，如 0/O、1/l/I；
- 相似希腊字形是否保持，如 φ/ϕ、θ/ϑ、ε/ϵ；
- 连字符、减号和负号是否正确；
- 撇号、导数符号、上划线、帽号、波浪号、粗体向量和黑板体是否保留；
- 绝对值、行列式、范数、取整符号和括号层级是否正确；
- 积分、求和、乘积的上下限及微分符号是否完整；
- 矩阵、向量和系数序列的元素顺序是否保持。

### 10.2 公式格式

排版源中优先使用结构化数学表达（如LaTeX、MathML或等效公式对象）。  
最终PDF中必须保证：

- 公式居中；
- 编号右对齐；
- 不越界；
- 多行等号对齐；
- 符号清晰；
- 文中统一引用“式（x）”；
- 公式与编号不得跨页分离；
- 长公式换行不得改变括号层级、运算顺序或等号对齐；
- 公式字体替换后不得出现空方框、缺字、错体或希腊字母变形；
- 表格中的公式不单独重排或转写，必须随原始表格裁剪图整体保留；但仍需读取并核对其符号、数值和跨章节关系。

### 10.3 公式不能只看单式

必须跨公式推导检查，例如：

- 式（1）—式（4）；
- 式（5）—式（12）；
- 式（13）—式（15）；
- 式（16）与光学倍增因子；
- 式（17）与图18几何关系。

### 10.4 原文公式简化或疑似错误

原文省略常量相位、近似项、中间步骤，或公式本身存在疑似转录/量纲错误时：

- 正文中的原编号公式默认按原文保留；
- 不得把“译者判断后的正确式”静默替换成原文公式；
- 必要时在公式后增加“译校注”，说明量纲、推导或跨章节证据；
- 若需要给出建议修正式，应明确标注“按上下文推测应为……”，并与原文公式分开显示；
- 只有当英文原始PDF本身清楚、而译文或OCR转录错误时，才直接修正译文公式，不需要把错误转录保留下来；
- 说明省略项可并入初始相位、零位偏置或校准参数时，必须说明这是解释，不得伪装成作者原句。

示例：

```text
译校注：由式（2）和式（3）严格展开时，式（4）的余弦项还应包含常量相位差。原文未显式写出该项，可理解为将其并入系统初始相位或零位偏置。
```

### 10.5 公式三层保真核验

每个编号公式以及关键行内公式必须至少通过以下三层核验：

1. **原文页图层**：直接查看英文原始PDF页面图像，确认每个符号、位置、编号和上下文；
2. **排版源结构层**：检查LaTeX、MathML或等效结构化公式表达，确认上下标、分式、根式、矩阵、积分、向量和符号没有被扁平化、OCR替换或错误转写；
3. **最终PDF渲染层**：生成PDF后放大检查，确认视觉呈现与原文一致，无缺字、错位、越界、字体回退和符号变形。

三层核验必须相互独立。不能因为排版源中的公式看起来正确，就跳过原文页图核对；也不能因为结构化公式表达正确，就跳过最终PDF渲染检查。

建议建立公式审计表：

| 式号/位置 | 原文页码 | 原文页图核对 | 排版源结构核对 | PDF渲染核对 | 变量定义 | 跨式关系 | 状态 |
|---|---:|---|---|---|---|---|---|
| 式（1） | 16 | 通过 | 通过 | 通过 | 已核对 | 与式（2）一致 | 通过 |

### 10.6 独立复核原则

终审公式复核不得只读取已经生成的译文公式再与其自身比较。第二轮复核应重新从英文原始PDF页图出发，独立重读公式，并重点核对：

- 第一轮最容易忽略的正负号；
- 系数向量中每个元素的位置和符号；
- 上下标、括号和积分上下限；
- 公式前后文字给出的变量定义；
- 原文中名称与数学定义是否一致；
- 简单代数、量纲和数量级是否合理。

若第二轮发现新问题，第一轮评分自动失效。

## 11. 第六阶段：表格处理

论文表格采用与图片相同的处理原则：**直接保留英文原始表格图像，不翻译、不重排、不重建。**

### 11.1 唯一允许来源

表格只能来自：

- 英文原始PDF内嵌页面；
- 或英文原始PDF页面的高分辨率裁剪。

不得从旧译文、网页、OCR结果、电子表格、出版社网页HTML表格或自动识别文本中重新制作。

### 11.2 表格本体必须原样保留

裁剪图中必须保留：

- 表号；
- 英文表题；
- 列名和行名；
- 全部数据；
- 单位；
- 脚注、注释和引文；
- 表内公式、矩阵、算法权重、系数向量；
- 正负号、零元素位置、括号、上下标和归一化因子；
- 跨页表格的续表标识、重复表头和续行内容。

**即使表格全部为英文，也保持英文原样。默认不另排中文表题，不翻译表头、行名、脚注或表内文字。**

### 11.3 绝对禁止

不得：

- 翻译表格本体；
- OCR后重新排版；
- 手工重新打字；
- 用Word表格、Excel表格、Markdown表格或HTML表格重建；
- 为追求“可编辑”而拆分成表A、表B或多张子表；
- 合并、拆分、转置、重排行列；
- 调整原数据的小数位、科学计数法、符号或单位写法；
- 删除看似重复的表头、注释、空白列或空白行；
- 把跨页表格重新拼接成作者原文中不存在的新表；
- 为适应页面而拉伸、压扁或裁掉任何单元格；
- 在表格图像内部增加中文标注、箭头、框线或译校说明。

### 11.4 裁剪与插入规则

- 以原文中的完整表格或完整续表区块为单位裁剪；
- 四周保留3～5 mm安全边距；
- 表号、英文表题和表下注释应与表格一起裁入；
- 不等比例拉伸；
- 输出分辨率建议300～400 dpi；
- 跨页表格按原始页序分别插入，不重新拼接；
- 表格图像宽度应保证最终PDF放大后数字、单位、上下标和脚注清晰可辨；
- 若表格过宽，优先横向页面、整页插入或适度缩放，不得拆列重建。

### 11.5 中文正文如何处理表格

中文正文只翻译作者在正文中对表格的叙述和引用，例如“结果见表2”。表格本体保持英文。

确需帮助基础较弱读者理解时，可以在表格外增加独立的“阅读提示”或“译校注”，但必须满足：

1. 不逐单元格翻译表格；
2. 不替代表格本体；
3. 不把解释写入表格图像；
4. 明确区分作者原文与译者说明；
5. 只解释阅读方法、变量关系或原文疑点，不重新制作中文表格。

### 11.6 表格技术信息仍须核验

“不翻译表格”不等于“不检查表格”。译校人员仍必须直接读取原始表格，并核对：

- 表号及正文引用；
- 行列顺序；
- 数据、正负号、小数位和科学计数法；
- 单位及量纲；
- 表内公式、矩阵、算法权重和系数向量；
- 脚注与特殊符号；
- 表内数据与正文、图、公式、摘要和结论中的重复数据；
- 表格是否存在作者原文内部矛盾。

若发现异常：

- 不修改原始表格图像；
- 在表格外增加最小必要的译校注；
- 明确写出原文数值、核验依据和疑点；
- 没有充分证据时标记“需作者或原始数据确认”。

### 11.7 算法表、矩阵和系数向量专项核验

含相移算法、滤波器系数、矩阵、权重、查找表、标定常数或多项式系数的原始表格，虽然不翻译、不重建，仍必须按公式同等级逐元素读取核验：

1. 直接查看英文原始PDF页图；
2. 按元素索引记录第1项至末项；
3. 核对每个正负号、零元素、重复系数、分母、根号和归一化因子；
4. 核对行列顺序、算法名称与对应公式是否一致；
5. 必要时计算正项数、负项数、零项数或简单校验和；
6. 检查排版源中嵌入的表格图像资产与原始裁剪图一致；
7. 导出PDF后放大检查，确认缩放、压缩和字体栅格化没有使任何元素不可辨认。

任何算法系数的数值、符号或位置在原文与最终显示之间发生变化，均按P0处理。

### 11.8 表格三层图像保真核验

每个表格至少通过：

1. **原文页图层**：确认表格完整边界、表号、英文表题、数据、单位、注释和跨页关系；
2. **排版源嵌入资产层**：确认使用的确为原始裁剪图，无重绘、无翻译、无重排、无裁切；
3. **最终PDF渲染层**：放大检查清晰度、比例、页边界、跨页顺序和全部单元格可辨识性。

建议建立表格核验表：

| 表号 | 原文页码 | 原始裁剪完整 | 未翻译/未重建 | 技术信息已读取 | 排版源图像一致 | PDF清晰完整 | 跨章节核验 | 状态 |
|---|---:|---|---|---|---|---|---|---|
| 表1 | 8 | 通过 | 通过 | 已逐项核对 | 通过 | 通过 | 与式（5）一致 | 通过 |

## 12. 第七阶段：论文元数据与参考文献

### 12.1 作者姓名

```text
A. Author
B. Author
C. Author
```

不得仅凭拼音推测中文姓名。

### 12.2 元数据

保留：

- 论文英文题目；
- 期刊名；
- 年份；
- 卷期；
- 页码；
- DOI；
- 作者；
- 机构；
- 通信作者；
- 收稿日期；
- 修回稿接受日期；
- 基金；
- ORCID；
- 版权。

可以增加中文题目，但不能删除英文检索信息。

### 12.3 参考文献

参考文献：

- 不翻译；
- 不重新打字；
- 不OCR重排；
- 不擅自修正DOI；
- 不改作者；
- 不改专利号；
- 直接照搬原论文页面或参考文献栏。

当参考文献从某一页中部开始，而同页上方仍有正文或致谢时：

若用户需要可搜索参考文献，应另做独立版本，不影响阅读版。

## 13. 第八阶段：跨章节核验

这是专业翻译与普通翻译的主要区别。

### 13.1 核验矩阵

| 核验对象 | 需要对照的内容 |
|---|---|
| 单位 | 表格、正文、图轴、公式量纲 |
| 图号 | 正文引用、图题、插图位置 |
| 章节号 | 正文前后引用、目录 |
| 自由度 | 图题、正文、结构功能 |
| 术语 | 摘要、正文、结论、表格 |
| 公式变量 | 首次定义、后续使用、图中符号 |
| 转角定义 | 坐标轴、图示、误差章节 |
| 性能指标 | accuracy、precision、resolution、uncertainty |
| 物理结构 | 正文描述、图内器件、光路 |
| 图内技术参数 | 子图标注、图题、正文、表格、公式、结论 |
| 符号层级 | 变量、下标、级次整数、曲线/功率标签是否混用 |
| 数值 | 表格、正文、图内标注、结论、参考文献原始结果 |
| 定义—名称一致性 | 术语名称、数学定义、分子分母方向、单位 |
| 数值合理性 | 基本公式复算、角度与NA、数量级、边界条件 |
| 公式渲染 | 原文页图、排版源结构化公式、最终PDF页面 |

### 13.2 典型错误

必须主动搜索：

- 原始表格中的单位与正文冲突；
- 正文引用不存在的章节；
- 图16被写成图17；
- 图示是二自由度，正文笼统写成三自由度；
- 图中Yaw/Pitch/Roll与正文定义不一致；
- 原文写reference prism，但图中实际为参考光栅和折转元件；
- 光学倍增因子误写成分辨力倍数；
- 原文公式省略相位项；
- “信噪比”等名称与其实际定义的分子、分母方向相反；
- NA、角度、波长、频率、量程等数值代入基本公式后明显不一致；
- 相机、扫描方式或物镜参数因字面直译而形成错误专业概念；
- 原始算法表中的单个系数正负号、元素顺序或归一化因子与正文公式冲突，或最终裁剪显示发生变化；
- 原公式被译者直接改成推测的正确式，但未保留原文和译校注；
- 图内周期、尺寸、角度或效率与图题、正文、表格或结论不一致；
- 数学变量与图例/功率标签混用，例如把整数衍射级次 \(m\) 与透射分量标签 \(T_m\) 视为同一层级；
- 作者姓名或英文人名顺序在正文中被擅自改写。

### 13.3 处理方法

- 对普通拼写、明显图号或章节号错误，有充分证据时可在译文中校正，并添加简短译校注；
- 对公式、算法系数、关键数值和单位，默认采用“原文保留 + 译校注说明 + 必要时给出建议修正式”的双层处理；
- 没有充分证据时，保留原文并标记待核对；
- 不静默修改关键数值、单位、公式和物理定义；
- 任何复算结果都必须区分“作者原文”“译者核验结果”和“建议修正”，不得混写。

## 14. 第九阶段：八轮质量检查

### 第一轮：结构完整性

检查：

- 页数；
- 章节；
- 段落；
- 图；
- 表；
- 公式；
- 算法表和系数向量；
- 参考文献；
- 标题层级。

### 第二轮：逐段原文对照

建立英文段落与中文段落一一对应关系，检查：

- 漏译；
- 重复；
- 错序；
- 合并过度；
- 增译；
- 限定条件丢失。

### 第三轮：术语与语境检查

全文搜索核心术语，并逐处判断语境：

```text
精度
准确度
分辨率
分辨力
二维
二自由度
同相
零差
垂直入射
正入射
校准
标定
回射器
逆反射器
栅格扫描
光栅式扫描
满阱容量
量子阱深度
有效孔径
有效数值孔径
```

不得只做全局替换，必须判断每一处属于何种器件、物理量或算法语境。

### 第四轮：公式原文保真专项检查

逐式从英文原始PDF页图重新核对：

- 式号和数量；
- 字母与希腊字母；
- 上下标；
- 正负号；
- 分数、根号和括号；
- 向量、矩阵和积分；
- 变量定义和跨式关系；
- 原文公式是否被静默改写。

### 第五轮：图片、原始表格图像和算法系数专项检查

逐一检查：

```text
图1—末图
表1—末表
式（1）—末式
全部算法表、矩阵与系数向量
```

对原始算法表必须逐元素读取核对，不得重建表格，也不得只核对表题和总体结构；同时检查原始表格裁剪图在排版源和最终PDF中是否完整、清晰、未翻译、未重排。对图片必须逐子图读取技术参数，并完成“图内参数—图题—正文—表格—结论”五向核验，不能只确认图片像素未变化。

### 第六轮：跨章节技术与数值合理性核验

检查：

- 单位；
- 图号；
- 章节号；
- 自由度；
- 转角；
- 基准；
- 物理量；
- 结论强度；
- 术语名称与数学定义；
- 基本公式复算；
- 数量级和边界条件；
- 原文疑点是否已用译校注透明处理。

### 第七轮：排版源结构与发布文件检查

检查：

- 独立公式是否使用结构化数学表达；
- 表格是否为英文原始PDF裁剪图，且表内公式、上下标和矩阵在最终显示中清晰完整；
- 图片是否为原始裁剪图；
- 排版源中是否存在占位符、调试标记、临时注释或路径残留；
- PDF元数据中的标题、作者、主题等是否正确；
- 最终PDF可重新打开、复制文本和正常渲染。

### 第八轮：最终PDF逐页渲染检查

生成最终PDF后逐页检查：

- 首页缺字；
- 字体；
- 公式；
- 数学符号；
- 图片；
- 表格；
- 页边界；
- 空白页；
- 图文重叠；
- 孤立标题；
- 公式与编号分离；
- 参考文献边界裁剪；
- 页码；
- 文件属性。

含公式、原始表格图像和特殊符号的页面应放大检查，不能只浏览缩略图。

**不能只检查排版源或PDF文本提取结果；必须检查最终PDF的实际页面渲染。**

### 第二轮独立终审：盲审式重新核验

八轮质量检查完成并修订后，还必须进行第二轮独立终审。第二轮不得把第一轮问题清单当作完整检查范围，而应：

1. 从英文原始PDF第一页重新开始；
2. 以原文为主线，不以现有中文译文为主线；
3. 假设第一轮仍可能遗漏问题；
4. 重新读取全部图内参数和子图文字；
5. 重新核对关键公式、变量定义、数值和单位；
6. 重新检查摘要、正文、图表和结论中的重复数据；
7. 专门寻找未被第一轮记录的新问题；
8. 发现任何新P0或技术性P1问题后，使第一轮评分和可交付结论立即失效。

第二轮终审不是“确认第一轮做过什么”，而是独立尝试推翻第一轮结论。

## 15. 内部评分与闭环修订机制

### 15.1 评分目的

内部评分不是形式化自评，而是正式交付前的质量闸门。  
翻译初稿、修订稿和终审稿均应重新评分，评分必须建立在英文原文逐段、逐图、逐个原始表格图像、逐式核验的证据之上。

**禁止为了尽快交付而虚高评分。**

只有同时满足以下条件，才允许向用户提供最终文件：

1. 综合评分不低于 **9.2/10**；
2. 不存在P0级问题；
3. 不存在尚未解决的技术性P1问题；
4. 关键分项达到规定最低分；
5. 最终PDF已实际生成、打开并检查；
6. 最终PDF已完成逐页渲染检查；
7. 连续两轮独立复核均达到9.2分或以上。

若任一条件不满足，必须继续内部循环修改，不得交付，不得提供下载链接，不得使用正式V1版本号，也不得以“可先阅读”“基本完成”等理由发送候选文件。

### 15.2 10分制评分表

| 评分项目 | 满分 | 主要检查内容 |
|---|---:|---|
| A. 技术含义与原文忠实度 | 2.5 | 物理含义、因果关系、限定条件、结论强度、技术事实是否准确 |
| B. 正文完整性与结构对应 | 1.0 | 是否漏译、重复、错序、误合并；章节和段落是否一一对应 |
| C. 专业术语与计量概念 | 1.1 | accuracy、precision、resolution、uncertainty、DOF及器件术语是否统一 |
| D. 公式、变量、单位与数值 | 1.5 | 原文页图、排版源结构和PDF渲染三层是否一致；字符、上下标、正负号、编号、变量解释、量纲、单位和数字是否正确 |
| E. 图片、图题与版权信息 | 1.2 | 是否原图裁剪；图内内容、子图、坐标轴、图例、来源是否完整 |
| F. 原始表格图像与跨章节一致性 | 1.0 | 是否直接使用原始表格裁剪图；表号、表题、表内内容是否完整；裁剪、缩放和PDF渲染是否忠实；表内数据与正文、图、公式、结论是否一致 |
| G. 中文科技表达与研究生可读性 | 0.8 | 是否通顺、严谨、少翻译腔，并避免误导基础较弱读者 |
| H. 元数据、参考文献与成品质量 | 0.9 | 作者、机构、DOI、参考文献边界、PDF文件命名、元数据、文本可搜索性与最终渲染 |
| **总分** | **10.0** |  |

### 15.3 关键分项最低门槛

即使总分达到9.2分，只要关键分项低于以下标准，也不得交付：

| 关键分项 | 最低分 |
|---|---:|
| A. 技术含义与原文忠实度 | 2.35 / 2.5 |
| D. 公式、变量、单位与数值 | 1.40 / 1.5 |
| E. 图片、图题与版权信息 | 1.10 / 1.2 |
| F. 原始表格图像与跨章节一致性 | 0.90 / 1.0 |
| B. 正文完整性与结构对应 | 0.95 / 1.0 |

下列情况直接判定为不通过，不允许以其他项目高分抵消：

- 有段落、公式、图片、表格或参考文献页缺失；
- 公式中的变量、上下标、正负号、单位或编号存在实质错误；
- 原始算法表、矩阵或系数向量中任一元素在最终显示中发生数值、符号或位置变化；
- 最终PDF中的数学符号因字体替换、渲染或换行而发生缺失、变形或歧义；
- 将原文疑似错误公式静默替换为译者修正式，导致原文与译文不再一一对应；
- 图片被重绘、AI生成、OCR重组、翻译图内文字或改变内容；
- 表格被翻译、重打、OCR重排、重建、拆分、拼接，或裁剪导致表号、表题、数据、单位、注释、跨页续行缺失；
- 作者姓名被猜测性翻译；
- two-DOF、accuracy、precision、resolution等关键术语造成技术误解；
- 存在未解决的图号、章节号、坐标定义或自由度矛盾；
- PDF存在乱码、缺字、图文重叠、原始表格图像缺失或不可辨、图片裁切或无法打开；
- 排版源中的独立公式结构已损坏，或最终PDF中独立公式不可正确显示；
- 参考文献被OCR重排后产生新的著录错误。

### 15.4 问题等级与扣分原则

#### P0：重大技术错误或交付阻断问题

示例：

- 公式错误；
- 算法系数、矩阵元素或权重符号错误；
- 公式在排版源与最终PDF之间发生符号丢失或结构变化；
- 图片内容变化；
- 关键单位错误；
- 大段漏译；
- 光路、自由度或物理原理被译错；
- 文件无法打开；
- 作者姓名被错误翻译；
- 图内关键技术参数与正文、图题或表格冲突而未发现或未说明；
- 在未完成终审前将内部候选稿作为正式V1交付。
- 在没有对应检查记录时声称已完成两轮审校、公式三层核验、PDF逐页检查或P0/P1清零；
- 生成或报告没有分项明细、扣分依据和计算记录支撑的精确高分；
- 伪造、补写或事后倒填QA记录，使其看起来早于实际检查完成。

处理规则：

- 出现任何P0问题，当前版本直接判定不合格；
- 不得计算为“9.2分以上”；
- 必须修复后从头重新评分。

#### P1：影响专业理解的问题

示例：

- 核心术语不规范；
- 技术结论被加强或弱化；
- two-DOF误作二维；
- 图文定义矛盾未说明；
- 关键参考文献或承接句遗漏；
- 公式简化未对初学者说明；
- 术语名称与其数学定义方向不一致而未说明；
- 明显的数值、量纲或基本公式矛盾未复算、未透明标注；
- 语境型术语按字面误译，虽未改变整篇结论但会误导专业理解；
- 图内非关键参数、图例含义或符号层级与正文不一致而未说明；
- 作者英文姓名顺序被擅自调整；
- 只检查图像完整性，未读取图内参数并完成交叉核验。

处理规则：

- 技术性P1不得遗留到最终交付；
- 修复后必须进行相关章节及全文术语回查。

#### P2：可读性与排版问题

示例：

- 标点、空格不统一；
- 图题不够自然；
- 页间留白较大；
- 局部翻译腔；
- 非关键格式不一致；
- PDF元数据明显错误、残留临时标题或生成信息影响正式使用；
- 参考文献页因裁剪不精确而重复出现已翻译的致谢或正文，但未造成条目缺失。

处理规则：

- 应尽量修复；
- 不得积累到明显影响研究生阅读或正式版观感。

### 15.5 闭环修订流程

每完成一个可交付候选版本，必须执行以下循环：

```text
完成内部Draft-A候选译文
    ↓
逐段对照英文原文
    ↓
逐图、逐个原始表格图像、逐式核验
    ↓
图内参数—图题—正文—表格—结论五向核验
    ↓
公式三层保真核验与算法系数逐元素核验
    ↓
跨章节核验与数值合理性复算
    ↓
建立P0/P1/P2问题清单
    ↓
按P0→P1→P2顺序修订为Draft-B
    ↓
全文术语与关联位置回查
    ↓
重新生成PDF
    ↓
逐页渲染检查PDF
    ↓
QA-1从零评分
    ↓
总分是否≥9.2且满足所有硬门槛？
    ├─ 否：继续内部修订，不得交付
    └─ 是：进入QA-2盲审式独立终审
              ↓
       QA-2是否发现新问题？
              ├─ 是：QA-1评分失效，继续修订并重新两轮审校
              └─ 否：完成第二次独立评分
                         ↓
                  连续两轮均≥9.2且全部硬门槛通过？
                         ├─ 否：继续内部循环
                         └─ 是：形成RC并进行发布检查
                                    ↓
                             第一次对外交付，命名为正式V1
```

不得沿用上一轮分数直接小幅加分。每次修订后必须从零重新评价。内部Draft、QA和RC阶段均不得占用正式V版本号。

```text

```

### 15.7 防止评分虚高

评分时必须遵守：

1. 不能因文档“看起来专业”而提高技术准确性得分；
2. 不能因中文流畅而忽略公式、图片、单位和跨章节错误；
3. 不能因问题来自英文原文而直接忽略，必须判断是否需要译校注；
4. 不能用“研究生大概能看懂”代替严格核验；
5. 不能用总分掩盖关键分项不合格；
6. 不能在没有逐页检查PDF时给成品质量满分；
7. 不能仅凭一次评分达到9.2就交付，必须连续两轮通过；
8. 发现新问题后，旧评分自动失效，应修订并重新评分；
9. 原文存在歧义时，不得猜测，应保留原文并标记待核对或加入译校注；
10. 翻译质量为最高要求，不人为限制思考时间、校验轮次或修订次数。
11. 不能把“公式数量正确”当作公式核验完成；必须核对每个符号及最终渲染。
12. 不能只抽查算法表；含系数、矩阵或权重的原始表格必须从页图逐元素读取检查，但不得重建。
13. 不能因已对原文疑点作出合理推断，就把推断后的式子直接当作原文呈现。
14. 不能仅凭自动脚本或文本比较结果判定公式保真，必须结合原文页图人工复核。
15. 不能把“文件已经成功生成”误认为“翻译已经完成”。
16. 不能在第二轮独立终审前向用户提供任何候选PDF链接。
17. 不能把用户交付后的“校验并评价”当作正常质量控制环节；交付后的校验只能是额外确认。
18. 不能因第一轮已经发现若干原文错误，就假设未发现的图内参数和交叉数据均正确。
19. 不能先写“9.2分以上”或“终审通过”，再寻找理由补齐评分表；评分结论必须是检查记录的最后输出。
20. 不能在缺少公式审计表、问题关闭记录或逐页检查记录时使用“已完成”“已通过”“无问题”等完成式表述。
21. 不能用两位小数制造虚假精确性；正式报告分数最多保留一位小数。
22. 第二轮复核在形成独立问题清单前，不得查看QA-1总分和可交付结论。
23. “暂未发现问题”不等于“无问题”；只有对应专项核验完成后才能使用“无P0问题”“技术性P1已清零”等表述。
24. 文件生成、转换成功、页数正确或视觉整齐，只能证明文件存在，不能证明翻译、公式或技术核验完成。

### 15.8 停止条件

只有满足下列全部条件，内部循环才可停止：

- 综合评分连续两轮不低于9.2分；
- 所有关键分项达到最低门槛；
- P0问题为0；
- 技术性P1问题为0；
- 正文、图片、原始表格裁剪图、公式和参考文献数量与原文一致；
- 跨章节疑点均已解决或透明标注；
- 最终PDF实际可用；
- 公式三层核验全部通过；
- 原始算法表、矩阵和系数向量已逐元素读取复核，且表格本体未被重建或翻译；
- PDF逐页渲染无缺陷；
- PDF元数据、实际basename和可搜索性已检查；
- 文件名符合规定，且实际basename为正常可读字符、未被URL百分号编码污染；
- 用户要求的交付格式全部齐全；
- Release Gate全部项目均为PASS，且机器发布记录完整。

在达到停止条件前，不得向用户发送任何候选PDF，不得提供下载链接，不得使用正式V1版本号，不得使用“已完成翻译”“最终版”“终审通过”等表述。


### 15.9 正式交付证据包

正式V1发布前，必须保留以下内部证据：

1. 文献结构盘点表；
2. 冻结术语表及术语变更记录；
3. 公式审计表；
4. 图内参数—图题—正文—表格—结论一致性表；
5. 原始表格图像保真表，以及矩阵、算法系数逐项读取核验表；
6. 原文疑点与译校注清单；
7. P0/P1/P2问题清单及关闭状态；
8. QA-1和QA-2两轮独立评分记录；
9. 排版源结构化公式、嵌入资产和PDF元数据检查记录；
10. 最终PDF逐页渲染检查记录；
11. 机器发布记录：最终文件绝对路径、Expected basename、Actual basename、二者逐字符比较结果、`%[0-9A-Fa-f]{2}` 检查结果、最终PDF实际页数、文件大小、必要时的校验和；必须能够证明URL编码仅存在于链接层，未污染实际文件名；
12. Release Gate总表：逐项PASS/FAIL、对应证据位置、最终结论 `ALL PASS` 或 `BLOCKED`。

证据包可以不全部展示给用户，但必须真实存在。没有可追溯证据时，不得仅凭口头说明宣称“已逐项核验”。

### 15.10 Release Gate：发布前统一硬闸门

RC形成后，不再使用“总体感觉正常”的方式发布，而是执行统一Release Gate。每一项必须记录 `PASS / FAIL / BLOCKED` 和证据位置。

| Gate | 检查项 | 必须执行的动作 | 通过条件 |
|---|---|---|---|
| G1 | RC身份 | 核对当前最终PDF是否由已通过QA-2的同一RC内容生成 | 一致 |
| G2 | P0/P1 | 读取问题清单与关闭记录 | P0=0，技术性P1=0 |
| G3 | 两轮评分 | 读取QA-1、QA-2独立评分及分项记录 | 连续两轮≥9.2且关键分项达标 |
| G4 | 公式 | 检查公式三层核验记录 | 全部PASS |
| G5 | 图/表 | 检查图文五向核验、表格三层保真和算法元素记录 | 全部PASS |
| G6 | 最终PDF | 实际检查文件存在并打开 | PASS |
| G7 | 页数/渲染 | 从最终PDF读取页数并逐页渲染 | 无缺页、无渲染失败、逐页检查完成 |
| G8 | 元数据 | 从最终PDF实际读取并核对 | PASS |
| G9 | basename | 从最终文件路径读取 `Actual basename` | 与 `Expected basename` 逐字符一致 |
| G10 | URL编码污染 | 对 `Actual basename` 检查 `%[0-9A-Fa-f]{2}` | 无误编码匹配 |
| G11 | 链接层隔离 | 核对链接编码未反向污染文件系统名称 | PASS |
| G12 | 发布状态 | 核对此前未向用户发送内部候选稿/候选链接 | PASS |

其中G9—G11必须按以下顺序执行：

```text
生成/重命名最终PDF
→ 从文件系统重新读取最终路径
→ 读取Actual basename
→ 与Expected basename逐字符比较
→ 执行%[0-9A-Fa-f]{2}检查
→ 再生成下载链接
```

禁止顺序：

```text
先拼接URL编码后的下载链接
→ 再把链接字符串当作文件名
```

Release Gate结论只允许两种：

- `ALL PASS`：允许生成/发送正式V1；
- `BLOCKED`：退回内部修订，不得发布。

任一Gate为FAIL、BLOCKED或缺少证据时，总结论必须为 `BLOCKED`。工具能力不足也属于 `BLOCKED`，不得推定为PASS。

### 15.11 完成声明的证据绑定

任何完成式声明都必须满足“声明对象明确、证据真实存在、记录时间早于声明、证据可定位”四项条件。

| 对外或内部声明 | 必须存在的最低证据 | 缺少证据时允许的表述 |
|---|---|---|
| 已完成全文翻译 | 章节—页码覆盖表、漏译检查记录 | 已生成完整候选译稿，尚未终审 |
| 已完成术语核验 | 冻结术语表、全文检索记录、变更记录 | 已建立初步术语表 |
| 已完成公式核验 | 公式审计表、原文页图记录、排版源结构检查、PDF渲染检查 | 公式已录入，三层核验尚未全部完成 |
| 已完成逐图核验 | 每图参数清单及五向核验表 | 图片已插入，图文一致性尚未全部验证 |
| 已完成两轮独立审校 | QA-1、QA-2两份独立问题清单和评分表 | 已完成第一轮检查/第二轮尚未完成 |
| 无P0问题 | P0专项清单及全部关闭状态 | 当前检查范围内暂未发现P0 |
| 无未解决的技术性P1 | P1清单、修改记录和全文回查记录 | 尚有P1待处理或尚未完成P1专项核验 |
| PDF逐页检查通过 | 逐页检查表，含页码和异常记录 | PDF已生成并可打开，尚未逐页检查 |
| 实际文件名检查通过 | Expected/Actual basename、逐字符比较结果、`%[0-9A-Fa-f]{2}`检查和最终文件路径记录 | 文件已生成，但实际文件名尚未机器核验 |
| 终审通过 | 全部硬门槛表、QA-1/QA-2、RC发布记录 | 当前仍为候选稿 |
| 得分达到9.2 | 分项表、逐项扣分表、计算式及硬门槛判定 | 暂不具备正式评分条件 |

不得用“已处理”“已核对”等模糊词代替证据。记录应能回答：检查了什么、依据是什么、发现了什么、如何处理、谁/哪一轮检查、何时完成。

### 15.12 评分生成顺序与精度限制

正式评分只能按以下顺序产生：

```text
建立检查范围
    ↓
逐段、逐图、逐个原始表格图像、逐式执行核验
    ↓
登记全部问题并标注P0/P1/P2
    ↓
逐项给出扣分项目、扣分值和证据位置
    ↓
计算A—H分项得分
    ↓
汇总总分
    ↓
检查关键分项最低门槛
    ↓
执行P0/P1及其他硬门槛否决
    ↓
形成最终评分结论
```

强制规则：

1. 不得预设目标分数，也不得以9.2门槛为锚点选择略高于门槛的数值；
2. 总分不得早于问题清单和分项评分表生成；
3. 正式对外评分最多保留一位小数，例如9.3/10；
4. 内部计算可以保留更多位数，但原始计算表必须保留，对外不得报告没有统计意义的两位小数；
5. 只有定性抽查、没有覆盖全文时，不得给出正式总分，可报告“初步区间”并明确抽查范围；
6. 任一关键核验尚未完成时，应标记“暂不评分”，不得用假设性高分代替。

### 15.13 逐项扣分表与可复算要求

评分表必须能从问题清单反向复算。每项扣分至少记录：

| 问题编号 | 分项 | 原文位置 | 译文位置 | 问题等级 | 问题说明 | 扣分 | 修复状态 |
|---|---|---|---|---|---|---:|---|
| QA1-P1-03 | C | 原文第1页 | 译文第1页 | P1 | precision误译为准确度 | 0.1 | 已修复/待复核 |

要求：

- 同一问题不得在多个分项重复扣分，除非明确说明其造成了多个独立影响；
- 修复问题后不能直接把分数恢复为满分，必须完成关联位置回查；
- 若发现新的问题，必须加入问题清单，不能只在文字评价中提及而不进入计分；
- 总分、各分项和逐项扣分之间必须数学一致；
- 评分表无法复算时，该分数无效。

### 15.14 评分封顶与否决规则

除既有关键分项门槛外，增加以下自动封顶或否决规则：

| 未完成或未解决事项 | 最高允许状态/分数 |
|---|---|
| 公式三层核验未全部完成 | 总分最高8.9，不得终审通过 |
| QA-2独立终审未完成 | 总分最高8.9，不得形成RC |
| 存在未解决的技术性P1 | 总分最高8.9，不得交付 |
| 最终PDF未逐页检查 | 成品项不得满分，总分最高8.9 |
| 参考文献未按原文直接保留且存在新增著录差异 | H项不得满分，总分最高9.0 |
| 图内参数五向核验未完成 | E、F项不得达门槛，总分最高8.9 |
| 交付证据包缺失关键记录 | 不得认定正式评分有效，不得终审通过 |
| 存在任何P0 | 当前版本直接不合格，不得给出“合格分” |
| 评分表无法由扣分明细复算 | 评分无效，必须重新评分 |

分数封顶不是代替修订，而是防止未完成关键流程时仍通过其他项目的高分“补偿”达到9.2。

### 15.15 第二轮独立终审的结论隔离

QA-2开始前，应建立新的检查工作表。QA-2在完成自己的第一版问题清单前：

- 不得查看QA-1总分；
- 不得查看QA-1的“可交付/不可交付”结论；
- 不得以验证QA-1已发现问题是否修改为唯一任务；
- 可以使用当前候选译文，但必须以英文原始PDF为主线；
- 必须独立登记至少“检查范围、未发现项、发现项和疑点项”。

QA-2独立问题清单形成后，方可与QA-1合并。若QA-2发现新的P0或技术性P1，QA-1评分自动失效，并重新进入修订—两轮复核流程。

### 15.16 实验结论的反证式核验

对摘要、实验结果和结论中的主要结论建立“结论—证据矩阵”：

| 结论表述 | 支撑图/表/数值 | 数据变化方向 | 统计或不确定度依据 | 是否完全支持 | 处理 |
|---|---|---|---|---|---|
| 提高准确度 | 图8、1.94→0.29 arcsec | 指标降低 | 给出k=2 | 支持，但原文动词方向有误 | 保留原文并译校注 |

必须重点检查：

1. “提高/降低”的方向是否与数值一致；
2. “保持不变/无影响”是否有统计波动、重复性或不确定度支持；
3. “显著”“约X倍”“普适性好”等强结论是否由实验范围支持；
4. 摘要、正文和结论是否使用了不同数值；
5. 稳定性、分辨力、准确度和不确定度是否被混用。

若作者原文结论超出数据直接支持范围，译文应忠实保留作者表述，同时增加最小必要的译校注，不得擅自替作者改写结论。

### 15.17 正式V1发布锁与状态撤销

制作流程应设置明确的发布锁：

1. Draft-A、Draft-B、QA-1、QA-2阶段禁止生成带`_GPT译_V1`的文件；
2. 只有RC全部硬门槛通过后，才允许复制或重命名为正式V1；
3. 正式V1生成时间必须晚于QA-2评分记录、证据包完成记录和RC发布检查；
4. 文件名正确不能反向证明终审已完成；
5. 若交付后发现本应在终审前发现的P0或技术性P1，应立即撤销“终审通过”和原评分，不得继续引用原分数；
6. 撤销后应记录：发现时间、问题性质、为何此前未发现、受影响范围、流程修正措施；
7. 后续修订文件的版本号由是否已真实完成正式交付决定，不能用V2掩盖V1提前发布的流程错误。

正式状态撤销不等于删除文件，而是明确该文件不再被称为“终审通过版”，并启动重新审校。

## 16. 译校注规范

### 16.1 适用情况

仅在以下情况使用：

- 原文单位明显错误；
- 图号或章节号错误；
- 图文定义矛盾；
- 公式存在明显简化、量纲疑点或疑似转录错误；
- 算法系数、角度、NA、频率、波长等数值关系存在可复算的不一致；
- 术语名称与其数学定义的分子/分母方向不一致；
- 作者原文术语不严谨；
- 为避免研究生形成错误理解而必须说明。

### 16.2 格式

```text
译校注：原文……
```

### 16.3 原则

- 简短；
- 客观；
- 给出证据；
- 不炫耀；
- 不写大段科普；
- 不替作者扩展新结论；
- 不修改原图；
- 不篡改原公式；
- 明确区分“原文写法”“核验依据”和“建议修正”；
- 对公式疑点优先采用“原文保留 + 译校注”的双层呈现。

## 17. 内部阶段与正式版本管理

### 17.1 内部阶段定义

```text
Draft-A：首次完整翻译候选稿，仅供内部处理
Draft-B：完成正文、术语、图片、原始表格裁剪、公式和跨章节修订后的候选稿
QA-1：第一次独立审校稿
QA-2：第二次盲审式独立终审稿
RC：满足全部硬门槛、等待发布检查的交付候选稿
```

内部阶段文件：

- 不得向用户发送；
- 不得提供下载链接；
- 不得使用正式V版本号；
- 不得在回复中称为“最终版”；
- 内部修订次数不受限制，也不影响正式版本号。

### 17.2 正式版本定义

```text
V1：第一次向用户正式交付的终审通过版
V2：V1交付后，因新增用户要求、新资料、新证据、官方勘误或用途变化产生的正式修订版
V3及以后：在前一正式版本基础上的后续正式修订版
```

以下情况不得作为生成正式V2的理由：

- V1候选稿尚未完成常规逐段核验；
- 交付后才首次检查图内参数；
- 交付后才首次检查公式渲染；
- 交付后才发现本应在终审前识别的术语、原始表格裁剪或元数据问题；
- 仅仅因为内部Draft-A改成Draft-B。

若上述问题发生，说明V1被提前交付，应当修正流程，而不能把“通常需要V2”视为正常质量策略。

### 17.3 每次内部修订必须记录

- 内部阶段标识；
- 修改位置；
- 原译文；
- 新译文；
- 修改理由；
- 是否影响全文术语；
- 是否影响图内参数一致性；
- 是否需要重新生成PDF；
- 图片是否保持不变；
- 公式是否保持不变；
- 修改是否影响原始表格裁剪、表格引用或表内数据的跨章节核验；
- 是否重新完成公式三层核验；
- 是否重新完成五向图文参数核验；
- 是否更新排版源并重新生成、检查PDF；
- 是否导致上一轮评分失效。

### 17.4 正式版本修订记录

正式V2及以后还必须记录：

- 相对于前一正式版本的变化；
- 变化来源是用户要求、新资料、勘误还是新增用途；
- 哪些正文、图片、原始表格裁剪图和公式保持不变；
- 是否需要重新进行两轮独立终审；
- 是否改变论文技术含义或仅改变排版形式。

### 17.5 禁止行为

不得每次修订时重新生成所有图片。  
不得为了小改动重新OCR参考文献。  
不得在没有对照原文的情况下“优化措辞”。  
不得用正式版本号记录内部质量控制过程。  
不得先交付低质量V1，再把正常终审工作安排到V2。  
不得为了满足“已生成文件”的表面进度而绕过内部QA-1和QA-2。

9. 重新生成PDF后逐页检查；

14. 若总分低于9.2分，或存在P0/技术性P1问题，继续内部循环修订，不得交付或提供链接。
15. 修订涉及图片或表格时，确认表格仍为未翻译、未重建的原始裁剪图，并重新完成图内参数—图题—正文—表格—结论五向核验。

17. RC通过发布检查后，第一次正式交付命名为V1；正式V1已经交付后才可因新增要求形成V2。
18. 修订完成后先更新问题关闭记录，再计算分项得分；不得先提高总分后补写修订依据。
19. 每个“已完成”声明必须引用对应内部记录；没有记录时标记为未完成。
20. 对外评分最多保留一位小数；缺少完整证据时暂不评分。
21. 若修订涉及实验结果或结论，重新执行结论—数据反证式核验。
22. V1文件名仅在RC发布锁解除后生成。
23. 发布或重生成正式PDF时，检查实际basename未被URL百分号编码污染：空格保持为空格，不得把 `%20`、`%2F`、`%3A` 等写入实际文件名；同时核验用户下载后的显示文件名没有保留百分号编码。

# 23. 本范式的核心经验

专业科技文献翻译最容易失败的地方，不是中文句子是否通顺，而是：

1. 图片经过重绘后出现事实变化；
2. 公式被OCR破坏；
3. 术语在不同章节切换；
4. 作者姓名被猜测性翻译；
5. 表格被自行翻译、重打或重建，导致数据、单位、表头或行列关系发生变化；
6. two-DOF被机械翻译为二维；
7. accuracy、precision、resolution混为精度；
8. 原文图号和章节号错误未被发现；
9. 解释性增译被写成作者原意；
10. 只检查排版源，没有检查最终PDF；
11. 为了追求速度，跳过逐图、逐式和跨章节核验；
12. 参考文献OCR重排后产生大量新错误；
13. 算法表被重建后仅一个系数正负号错误，却因“整体看起来正确”而漏检；
14. 原文疑似错误公式被直接改成译者修正式，失去原文保真性；
15. 公式在排版源中正确，但生成PDF后因字体或换行发生符号缺失、变形；
16. 术语按字面翻译，未结合相机、扫描方式、物镜等具体语境；
17. 原文术语名称与数学定义矛盾，却未增加译校注；
18. 未用基本公式复算NA、角度、单位和数量级；
19. 参考文献页裁剪不精确，重复正文或致谢；
20. PDF元数据、实际文件名或文本可搜索性未检查，降低成品可信度；
21. 只确认图片像素未变化，却没有读取图内尺寸、周期、角度和效率；
22. 图内参数与图题、正文或表格冲突，直到用户交付后复核才发现；
23. 把内部首次完整稿误命名为正式V1，导致正常终审工作被迫以V2形式完成；
24. 第二轮复核只检查第一轮问题清单，没有从原始PDF重新寻找新问题；
25. 文件生成成功后立即提供下载链接，没有等待全部质量闸门通过；
26. 把范式中的9.2门槛当作评分锚点，生成一个略高于门槛但没有明细依据的分数；
27. 把“应该完成两轮审校”写成“已经完成两轮审校”，却没有QA记录；
28. 报告精确到两位小数的分数，制造经过严格量化的假象；
29. 用“暂未发现问题”替代“专项核验完成且问题为零”；
30. 第二轮审校提前看到第一轮高分和可交付结论，形成确认偏差；
31. 只检查译文是否忠实照抄数据，没有反向检查数据是否支持作者的结论；
32. 正式V1文件名在RC完成前就已生成，使文件名反过来推动错误交付。
33. 将下载链接中的URL编码误写进实际文件名，例如把空格保存为 `%20`，导致用户下载后的文件名可读性差且命名不规范。
34. 规范中虽然写了“必须检查”，但没有真正调用工具或读取最终文件，就根据预期结果声称“已检查通过”。

高质量翻译的正确路径是：

> **原文结构盘点 → 术语与语境冻结 → 逐段翻译 → 原图裁剪 → 原始表格整体裁剪并保持英文原样 → 图内参数五向核验 → 独立公式三层保真核验 → 原始算法表逐元素读取核验 → 跨章节与数值合理性核验 → 原文疑点双层呈现 → 排版源结构检查 → PDF逐页放大检查 → QA-1独立审校 → QA-2盲审式终审 → RC发布检查 → 机器Release Gate → 第一次正式交付V1。**

速度不是首要指标。对于高难度仪器与精密测量论文，不人为设置思考时间、校验轮次或修订次数上限。候选译文必须经过内部评分闭环；不足9.2分时继续循环修改，直至连续两轮通过质量门槛。内部需要修改多少轮都不应让用户承担，也不应占用正式版本号。第一次向用户交付的V1就应是终审通过版本；后续V2只服务于真正新增的要求、证据或用途。最终目标是让研究生第一次收到文件时即可放心阅读、理解和引用。

# 24. V1.5升级记录

相对于V1.4，本版新增并强化：

1. 论文表格改为与图片相同的原始图像保真处理；
2. 表格必须直接取自英文原始PDF，高分辨率整体裁剪；
3. 表号、英文表题、表头、行名、数据、单位、注释、脚注和表内公式全部保持英文原样；
4. 明确禁止翻译表格本体、OCR重排、手工重打、重建为可编辑表格、拆分、拼接、转置和重排行列；
5. 跨页表格按原页顺序分别保留，不重新拼接；
6. 中文正文只翻译作者对表格的叙述，必要说明只能写在表格外；
7. 表格及表内公式采用“原文页图/原始裁剪图—排版源嵌入资产—最终PDF渲染”三层图像保真核验；
8. 算法表、矩阵和系数向量虽然不重建，仍必须从原图逐元素读取并完成跨章节核验；
9. 论文表格不要求可编辑，始终以原始英文裁剪图保真为最高优先级；
10. 评分表、检查清单、主提示词、续译提示词、终审提示词和修订提示词均同步采用上述规则。

本次升级继续保留V1.4的证据绑定、评分防伪、两轮独立终审、正式发布锁和失效撤销机制。核心变化是：**表格以原始英文图像的事实保真为最高优先级，可读性和可编辑性不得凌驾于原始数据保真之上。**

# 25. V1.6升级记录

相对于V1.5，本版新增并强化：

1. 新增“实际文件名与URL编码隔离”规则，明确文件系统basename与下载链接编码属于两个不同层级；
2. 明确实际文件名中的空格必须保留为空格，不得主动写成 `%20`；
3. 明确 `%20`、`%2F`、`%3A` 等百分号编码仅允许存在于URL/下载链接传输层；
4. 禁止在创建正式PDF前对实际文件名执行URL encode；
5. 正式发布前必须读取实际basename，而不能只检查Markdown链接或浏览器显示；
6. 新增 `%[0-9A-Fa-f]{2}` 形式的URL编码污染检查；
7. 正式论文交付物改为仅PDF，取消PDF/DOCX成对输出要求；
8. 正式交付证据包新增实际basename与链接显示名记录；
9. 停止条件、发布前最后闸门、成品检查清单、主提示词和修订提示词均同步加入文件名编码检查；
10. 保留V1.5全部原始表格图像保真、证据绑定、评分防伪、公式三层核验、图文五向核验和发布锁规则。

本次升级解决的是**交付工程层面的文件命名完整性**，不改变V1.5既有的翻译质量评价体系。其原则是：**实际文件名保持人类可读，URL编码仅服务于链接传输，二者不得相互污染。**

# 26. V1.7升级记录

相对于V1.6，本版新增并强化：

1. 正式论文交付物改为**仅PDF**，默认不再生成或交付DOCX；
2. 内部排版源可采用Markdown、LaTeX、HTML或其他结构化源文件，但不作为默认交付物；
3. 公式三层核验改为“英文原始PDF页图—排版源结构化数学表达—最终PDF渲染”；
4. 表格三层保真核验改为“英文原始PDF页图/原始裁剪图—排版源嵌入资产—最终PDF渲染”；
5. 取消DOCX可编辑性、OMML结构和DOCX文档统计属性作为交付门槛；
6. 增加最终PDF文本可搜索性、元数据、实际basename与下载显示名检查；
7. 再次强调：实际PDF文件名中的空格必须是真实空格，任何 `%20`、`%2F`、`%3A` 等只允许出现在传输URL中，不得进入实际basename；
8. 正式发布记录必须同时核对“文件系统中的真实basename”和“用户下载后的显示文件名”，发现百分号编码污染时必须重新生成或重命名后再交付。

V1.7的目标是减少不必要的中间交付格式，把质量控制集中到最终PDF本身，同时保持原文、公式、图、表和计量技术信息的严格保真。

# 27. V1.8升级记录

相对于V1.7，本版不降低任何既有翻译、公式、图片、表格、参考文献、评分和两轮终审要求，重点将“规则要求”升级为“可验证执行协议”：

1. 新增第0章“执行协议：证据优先、状态机与机器验证”；
2. 明确“能机器验证的，不得只靠语言判断；能读取实际值的，不得用预期值代替”；
3. 建立 `INPUT → INVENTORY → TERM-FROZEN → DRAFT-A → DRAFT-B → QA-1 → REVISE → QA-2 → RC → RELEASE-GATE → V1-RELEASED` 状态机；
4. 新增机器可验证项目表，覆盖最终PDF存在性、可打开性、页数、逐页渲染、元数据、实际basename、URL编码污染和最终文件一致性；
5. 将原“发布前最后闸门”重构为统一Release Gate，并要求每项记录 `PASS / FAIL / BLOCKED` 和证据位置；
6. 明确工具能力不足不能推定PASS，必须标记为BLOCKED；
7. 强化文件名检查：必须分别记录Expected basename与Actual basename，并逐字符比较；
8. 强化 `%[0-9A-Fa-f]{2}` 检查：必须针对从文件系统实际读取的Actual basename执行，而不是针对下载链接或预期名称；
9. 明确网页或下载链接中的 `%20` 可能只是传输层编码，不能反向污染实际文件名，也不能单凭链接判断basename；
10. 正式下载链接必须在实际basename机器核验通过之后生成；
11. 正式交付证据包新增机器发布记录和Release Gate总表；
12. 正式交付验收清单增加Expected/Actual basename、实际读取来源、URL编码隔离和Release Gate检查；
13. 将原超长主提示词替换为一份简短启动提示词，避免重复整份范式造成注意力稀释；
14. 新增“规范写了但未真正执行工具检查，却声称已经通过”这一典型失败模式。

V1.8的核心原则是：

> **规则负责定义质量，证据负责证明执行，Release Gate负责决定能否发布。**

在V1.8中，“生成了文件”与“通过了质量控制”被明确视为两个不同事件；只有最终文件经过实际机器检查且全部硬门槛通过，才允许第一次正式交付V1。
